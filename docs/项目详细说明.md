# 智能小秘书 · MCP + Agent + Gradio

> 一个可本地运行的中文智能助理项目。  
> 技术栈：**LangGraph + LangChain + MCP + Gradio**，推理模型使用 **DeepSeek**。

---

## 一、这个项目是什么

需求清单与对应实现：

| 需求               | 本项目对应能力                                   |
| ---------------- | ----------------------------------------- |
| 有完整的操作界面，并支持流式输出 | Gradio 6 界面，`astream` 流式逐字输出，工具调用折叠展示     |
| 可以获取网络上公开的数据     | MCP 工具 `my_search_tool`                   |
| 可以解析和提取网页内容      | MCP 工具 `fetch_webpage`                    |
| 可以自动分析数据，并生成分析图表 | MCP 工具 `analyze_and_chart`（matplotlib 出图） |
| 可以查询火车票、机票       | MCP 工具 `query_train_ticket`（12306）        |
| 可以规划出行路线         | MCP 工具 `plan_route`（OSRM + Nominatim）     |
| 规划菜单 / 减肥菜谱等     | 由模型在通用对话能力上完成，可配合 `get_weather`           |

架构上采用相同的分层思路，只是把「别人部署在 ModelScope 上的公共 MCP」换成了  
**本项目自带的本地 MCP 服务端**，因此换台机器也开箱即跑。

```
┌────────────────────┐   MCP (streamable_http / sse)   ┌──────────────────────┐
│  Gradio 智能小秘书  │ ─────────────────────────────▶ │  本地 FastMCP 服务端  │
│  agent/app.py      │                                │  mcp_server/          │
│        │           │ ◀───────────────────────────── │  搜索/网页/计算/天气/  │
│        ▼           │        tools / prompt / resource│  火车票/路线/图表      │
│ LangGraph ReAct    │                                └──────────────────────┘
│ create_react_agent │
│        │           │
│        ▼           │
│  DeepSeek ChatOpenAI│
└────────────────────┘
```

| **`agent/my_agent.py`**       | 【单 Agent】核心编排：`MultiServerMCPClient` 拉取工具 → `create_react_agent(llm, tools, prompt, checkpointer=InMemorySaver())`。一个大脑 + 全部工具。                                          |
| **`agent/multi_agent.py`**    | 【多 Agent】`StateGraph` 五节点：`supervisor`（调度）→ `researcher`/`travel`/`data`（三专家，各有独立 LLM 与专属工具）→ `summarize`（汇总发言）。含 `EXPERTS` 分工表。                    |

| **`run.py`**                  | 一键启动脚本，先拉起 MCP 服务端并探测端口，再启动界面，退出时回收子进程。                                                                                                                         |

## 四、两种编排模式（单 Agent / 多 Agent）

界面顶部有一个「🧠 编排模式」开关，可随时切换，两种模式共用同一套工具与界面：

| 模式 | 结构 | 特点 |
|---|---|---|
| **单 Agent（ReAct）** | 1 个 LLM + 全部 10 个工具 | 快、省、链路短；适合单步任务 |
| **多 Agent（调度 + 3 专家）** | 1 个调度中心 + 研究/出行/数据 三位专家 | 分工清晰、可观测；适合跨领域复杂任务 |

**多 Agent 的界面表现**：能看到 `👤 交接给【出行专家】(travel)` 这样的交接卡片，
工具卡片也会标注 `（出行专家）`，完整呈现「谁在干活」的分工轨迹。

> 详细对比（架构图、代码差异、开销、适用场景、实测对照）见 **`MULTI_AGENT.md`**。

命令行单独验证多 Agent：

```bash
python -m agent.multi_agent
```

## 六、设计约定（与原参考实现保持一致）

1. **MCP 传输协议可切换**：`streamable_http`（默认）与 `sse` 两套启动脚本并存，  
   对应原项目 `start_streamable_server.py` / `start_sse_server.py`。
2. **连接配置是普通 dict**：`{名字: {url, transport}}`，与  
   `MultiServerMCPClient({...})` 的入参形式完全一致，新增远程 MCP 只是加一个键。
3. **短期记忆 = thread + checkpointer**：`InMemorySaver()` 按 `thread_id` 隔离，  
   与《企业级 Agent 记忆系统实战指南》中「短期记忆靠 thread + checkpoint」的结论一致；  
   界面上点「清空对话」会同时换一个 `thread_id`，等于开一段全新记忆。
4. **工具调用可视化**：`ToolMessage` 单独渲染为 `🛠️ 已调用工具 xxx` 折叠卡片，  
   便于观察 Agent 的推理轨迹（对应《面试热门——Agent 项目的追踪、评估和可观测》的「轨迹层」观测）。
5. **密钥零硬编码**：所有密钥走 `.env` → `env_utils.py`。

## 七、扩展：接回原参考实现的远程 MCP

编辑 `config/mcp_config.py` 的 `REMOTE_MCP_SERVERS`：

```python
"gaode_mcp_server_config": {
    "url": "https://mcp.amap.com/mcp?key=你的高德Key",
    "transport": "streamable_http",
    "enabled": True,          # 改成 True
},
```

再在 `agent/my_agent.py` 里用 `create_agent(include_remote=True)` 即可。  
原参考实现里那 5 个远程服务端（智谱搜索、高德、fetch、12306、图表）合计能挂出 50+ 个工具，  
挂载后 Agent 能力会显著变强。

- **`plan_route`**：地理编码优先用 open-meteo（稳定），失败才退到 Nominatim（偶发 502）；  
  地址精确到「城市 / 区」级别，门牌号级解析可能不准确。

## 九、附：可观测与记忆设计的呼应

本项目虽然只是一个演示级应用，但刻意对齐了参考实现里两篇方法论文章的结论：

- **《企业级 Agent 记忆系统实战指南》**：短期记忆 = `thread_id` + `InMemorySaver`（`agent/my_agent.py`）；  
  界面上「清空对话」同时更换 `thread_id`，等价于开启一段全新记忆。
- **《面试热门——Agent 项目的追踪、评估和可观测》**：`ToolMessage` 被单独渲染成  
  `🛠️ 已调用工具 xxx` 折叠卡片，让「工具调用轨迹」对用户可见 —— 这正是文中「轨迹层评估」依赖的数据。
